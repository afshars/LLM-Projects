# HANDOFF part 10: Busy Blocks (route plan/busy-blocks)
- NEW `state/busy-blocks.ts` (`busyBlocksStore`): GET /busy-blocks takes ONE `date`, so a week = 7 GETs, kept per date. `load()` fetches only days never fetched / failed (`{force:true}` = Refresh); a language change rebuilds the view and sends nothing. Per-day request token (newest answer wins), reset on logout, late answers dropped, 401 -> session guard.
- `add()` POSTs, inserts into the loaded day (sorted by start), moves the screen to the week of the new block, then `invalidateDailyPlan()`. `remove()` DELETEs, drops the block locally (no refetch), then `invalidateDailyPlan()`; a 404 counts as deleted; other errors reject so the ConfirmDialog shows them and stays open.
- Pure helpers there: `validateBusyBlock` (HH:MM, end STRICTLY after start, same rule as the backend; error codes, no text), `buildBusyBlockBody` (blank label omitted, never null), `weekStartOf/weekDates/todayIso/trackSpan`. Dates are "YYYY-MM-DD" strings (UTC math, no time-zone shift).

Each day = heading + 24 h track (decoration, aria-hidden) + a real list; delete button per block -> `confirmDialog({kind:"delete"})`, then focus goes to that day's heading + live announcement.
