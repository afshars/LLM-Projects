# HANDOFF part 11b-4a: Brain Dump review panel + the confirm request. Error UI and success UI are NOT here (11b-4b).
- The found items now render inside the shared `reviewAndConfirm` panel (`views/brain-dump.ts`, `reviewPanel()`). Its notice "Nothing is saved until you confirm" (`dict.ui.review.notSaved`, fa + en) is always visible: normal, all items removed, in flight, after language change. Nothing found = no panel (nothing to confirm; the old "No items were found" + "nothing saved yet" notes stay).
- Single source of truth stays `brainDumpStore.items`. The panel keeps its own copies, so `renderItem` draws `items[ctx.index]` and ignores the copy; `onConfirm` ignores the panel's array too: `store.confirm(todayIso())` reads the working list. The panel's Remove button is off (`removable:false`): Delete stays card Delete -> confirmDialog -> store. Cards are now `div.brain-item` (were `li`; the panel owns the `li`). Same class names.
- `state/brain-dump.ts`: NEW `confirmStatus` idle|submitting|success|error, `confirmError` (ApiError, use `.kind`), `confirmResult` (`{saved}`), exported `isConfirmFrozen(state)`. NEW `confirm(logDate)`, `discard()`.
  - `confirm` sends `{log_date, items}` = working list at click time, via `apiClient.confirmBrainDump` (the only caller). One at a time (second call shares it). After `success` a second `confirm` sends NOTHING and returns the saved answer (the route ADDS rows).
  - Refusals send nothing, kind `validation`, `message` = reason code (not for display): `notReady`, `noItems` (state untouched), `invalidDate` / `invalidItems` (recorded as confirmStatus error).
  - While `submitting` and after `success` the list is frozen: `editItem` -> notReady, `deleteItem` -> false, `submit()` rejects (`message: "confirming"`). A new run, `discard()`, `reset()`, logout clear all three confirm fields. 429: rejects, no error stored, status restored. 401: session guard clears the store. NO retry in the store.
- `log_date` = `todayIso()` from `state/busy-blocks` (device-local calendar day, read at click time). If the profile has its own time zone that should win, change that one line in `reviewPanel()`.
- In flight (panel's `submitLock`): panel `aria-busy="true"`, Confirm, Discard, every Edit/Delete and "Sort my thoughts" disabled (`.disabled` property, not only the fieldset), double click/submit = one request. The panel is NOT redrawn for the status change (the focused button keeps its node); a language change mid-request rebuilds it locked, still one request. Confirm is also off with no items (visible reason: panel's own empty note) and while a card editor is open (visible reason, because typed-but-unapplied values would NOT be sent), and after `success`.
- Discard (panel's cancel): back to the form, typed text kept, `store.discard()`; asks via confirmDialog only when there are edits; off in flight.
- `lib/ui/review-and-confirm.ts`, all optional, defaults unchanged: `items` may be readonly, `removable`, `showErrors` (false = no built-in banner; 401 hand-off and 429 "please wait" still happen), `frozen`, `blockedReason`, `headingLevel`; `aria-busy` on the panel (follows the primary button, so NOT on during the 429 cooldown) and a `ui-review__blocked` line. Used by every caller.
