4. **Invalidate functions:** `invalidateTaskFailures()`, `invalidateDistractions()`, `invalidatePatterns()` (state/behavior.ts). Each sends its slice to idle (data dropped) and discards any answer still in flight. If that tab is on screen it reloads at once; otherwise on its next visit. Call them after a record is added (16b/16c) or patterns are recomputed (16d). Under the hood: `behaviorStore.invalidate(name)`.
5. **Loading rules** (state/behavior-flow.ts): `ensureBehaviorLoaded(tab)` sends only when the slice is idle (first visit); revisits, remounts and language changes never refetch; a failed tab is NOT retried by itself. `refreshBehaviorTab(tab)` is the explicit Refresh / "Try again" (skipped while a request runs). Both resolve `"ok" | "failed" | "skipped"`, never reject (the error is in the slice). 401 -> `handleAuthExpiry`. Data is kept while a refresh runs and after a failed refresh (the view currently hides it behind the skeleton/error).
