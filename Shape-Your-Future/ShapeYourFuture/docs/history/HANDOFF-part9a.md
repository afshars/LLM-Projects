# HANDOFF part 9a: daily plan view + language-change refetch bug
- Cause: app.ts redraws the whole view on a language change and `renderDailyPlan` called GET /daily-plan every time it was built. Fix: the plan now lives in NEW `state/daily-plan.ts` (`dailyPlanStore`: status idle|loading|ready|error, `plan`, `error` as ApiError, `invalid`). `load()` fetches only when idle (first visit), with `{force:true}` (Refresh / Try again) or when `invalid`. A request in flight is never repeated; a late answer after reset/logout is dropped; 401 -> journey.reset() clears it.
- `invalidateDailyPlan()` exported from `state/daily-plan.ts`: marks stale, sends nothing, no-op before the first load; an invalidate during a request keeps the result stale. Busy Blocks / Plan confirm should call it after they save.
- Already wired (the old "reload on every visit" used to cover these): hours saved (views/context.ts), goal decomposed (state/goals.ts), planning item leaves the list (state/planning-required.ts removeItem: manual submit and proposal accept/edit), next action done (dashboard + goal-workspace stores), focus finished / feedback sent.
- `views/daily-plan.ts`: renders through `asyncPanel` (list skeleton, error + Try again via `errorMessage(kind)` at render time, empty via guide). "Refresh plan" button (disabled while loading). The two 400s of GET /daily-plan (hours missing / nothing plannable) are shown as an empty plan with an explanation, not as an error. "What should I do now?" is shown whenever a plan answer exists, also when it has no items.
- Empty plan: `emptyStateGuide` with three links: Plan (planning-required route), Goals (goals/list), active hours (CONTEXT_SETUP). Primary = hours when hours are missing, else planning. `emptyStateGuide` got an optional `extraActions` (backward compatible) to carry the third link.
- i18n: 11 new keys in `plan` (en + fa; `fa` is typed as `Dictionary`, so parity is compile-checked). Old `plan.noHours`, `notReady`, `empty`, `setHours` are kept (now used as descriptions / not removed).
- Tests: NEW `smoke/daily-plan-state.test.ts` (11), `smoke/daily-plan-view.test.ts` (12, includes the language switch through the real `startApp`: one request).
- RUN: `tsc --noEmit` clean, `vitest run` all pass, `npm run build` ok.
- Not changed: the "What should I do now?" box and per-item Start Focus state are local to a render, so a language change still resets them (no request is made). Not part of this bug.
