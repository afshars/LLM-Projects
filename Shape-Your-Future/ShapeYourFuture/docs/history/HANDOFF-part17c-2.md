# Part 17c-2 — Preferences: change summary + Save (HANDOFF)
**REMOVAL (read from backend, not guessed):** PUT /user-intelligence/preferences takes a bare `dict` and does `merged.update(body)`. A key can be added or overwritten, NEVER removed: omitting it keeps it, `null` is stored as a value, `{}` changes nothing, no replace mode, no DELETE route; the profile `preferences` field merges the same way. A rename = new key added, old key stays. So removal is NOT encodable: `PREFERENCES_REMOVAL_SAVEABLE = false`; `encodeRemovals()` is the one place to change if a backend delete/replace appears.
**PUT body:** `{ <key>: <value>, ... }` = only added + changed keys, each whole (string / finite number / boolean). Never null, never an untouched key, never a locked (list/object/null) row. Built by `diffForPartialPut(data, rowsToDict(draft))` (no `nullable`).
**Behaviour I chose (the safe reading):** summary lists removed keys with a warning "the server can't remove preferences yet, these stay after you save"; Save is disabled when the draft only removes (hint says why; Discard still offered); after a save the server's answer wins, so a removed key reappears and the status line adds "the server kept these removed preferences: …". No confirmation dialog. **Decision for you:** keep Remove in the editor, or ask for a backend delete/replace.
`computePreferencesPut(original, rows) -> { changed (body non-empty), dirty (any difference, drives Discard), body, summary:{added,changed,removed} }` in `state/ui-preferences-save.ts`. Flow `state/ui-preferences-save-flow.ts` (`sendUiPreferencesSave`, `discardUiPreferencesEdits`); view `views/my-profile-preferences-save.ts`, ids `#my-profile-preferences-save-{button,discard,retry,problems,hint,status,error,wait,summary}`.
**Ambiguous:** (1) "keys only; long values truncated": I show keys only and cut keys over 40 chars (full key in `title`). (2) service docstring says "deep-merge" but the code is a shallow `update`; irrelevant to the UI (it never edits object values). (3) 200 with a non-object body = error kind "unknown"; a dropped connection after the server applied shows an error, retry re-sends the same values (idempotent).
**Deviations:** (a) I do NOT call `invalidateUiProfile()` as 17c-1 suggested: it drops the Profile form's unsaved edits. Instead `uiProfile.data/draft.preferences` are updated in place. (b) `diffForPartialPut.ts` edited (entries + `Object.fromEntries`): a preference named `__proto__` was silently dropped from `body`; no other behaviour changed.
**Also:** typing while a save runs is kept and stays unsaved; errors keep the ApiError kind and re-translate on language change; 429 uses submitLock ("please wait", 3 s); 401 -> login.
